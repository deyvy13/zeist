<Callout type="success" title="Quick answer">
Revit can **export a schedule** to a delimited text file that Excel opens, but it has **no native way to import changes back** into the model. To bulk-edit parameters in Excel and push them back to Revit, teams use **Dynamo** — which has nodes to read and write spreadsheets — or a **Revit–Excel sync plugin**. The technical key is to include each element's **unique ID** in the sheet, lock the columns that can't be edited, and validate data before writing it, so no value ever lands on the wrong element.
</Callout>

<Callout type="info" title="Glossary: the terms you'll read, in plain language">
- **Schedule** — The Revit table that lists elements and their data: doors, rooms, walls, equipment.
- **Parameter** — Any piece of data on an element: code, material, manufacturer, cost item, area.
- **Type vs. instance parameter** — A type parameter is shared by every element of that type; an instance parameter belongs to one element.
- **Unique ID** — Each element's internal code, which never changes. It's how you know which element each row belongs to.
- **Read-only parameter** — One Revit calculates and can't be written, like a room's area.
- **Round trip** — Exporting to Excel, editing, and pushing the changes back to the model.
- **Plugin** — A program installed inside Revit that adds its own buttons to the toolbar at the top.

No programming jargon. This is written for BIM coordinators, modelers and project managers.
</Callout>

## Why everyone wants Excel

Some data is much faster to enter in a spreadsheet than in the model:

- **Cost codes** so the takeoff comes out organized by estimate.
- **Asset and manufacturer data** for the handover to the owner who'll operate the building.
- **Room names and numbers** on a large project.
- **Classifications** the client or agency requires.
- **Door, window and equipment data** that comes from a supplier in a spreadsheet.

In Excel you filter, fill down, sort and review at a glance. In Revit, every value is a click on an element. That's why every team ends up wanting the same workflow: **get the data out, edit it in Excel, and push it back**.

<TopicCard step="1" title="1. What Revit allows natively" time="~5 min">

**Export, yes.** Revit exports any schedule to a delimited text file that Excel opens without trouble. Useful for reports and takeoffs.

**Import, no.** There's no native option to take that edited file and update model parameters. The round trip stops halfway.

**Editing inside the schedule, yes — but slowly.** You can type values into a schedule and they apply to the element. For dozens of values it works. For thousands, it's the week of work we mentioned.

<TopicCard step="2" title="2. Why the round trip is delicate" time="~7 min">

Pushing data back into the model looks trivial, and it's where the most models get damaged. These are the real risks:

**Rows that lose their element.** If the sheet doesn't carry each element's unique ID, once you sort or filter in Excel you no longer know which row is which door. The value lands on another element.

**Read-only parameters.** A room's area or a wall's length is calculated by Revit. If someone edits them in Excel, the import can't write them — or worse, it tries and fails halfway.

**Type vs. instance.** Changing a type parameter on one row changes **every** element of that type. If two rows of the same type were edited differently in Excel, one of the values is lost.

**Formats and units.** A number stored as text, a decimal comma instead of a point, meters instead of millimeters.

**Duplicated or deleted rows.** Someone copies a row to "add" an element that doesn't exist in the model, or deletes a row thinking it deletes the element.

<Callout type="warn" title="The error nobody sees">
The worst case isn't a failed import: it's one that succeeds **with the value on the wrong element**. No error, no warning, and the bad data shows up months later in the takeoff or the owner handover.
</Callout>

</TopicCard>

<TopicCard step="3" title="3. Dynamo or a plugin: two valid routes" time="~6 min">

**Dynamo** has nodes to read and write Excel sheets. With a well-built graph you can export, edit and import. It's a good option for a one-off or for proving the logic.

Its limits show up in daily use: it depends on whoever can open the graph, error handling is basic, and it slows down with thousands of elements. Validating every value before writing it takes a complex graph.

A **sync plugin** is a button on the toolbar: export, edit, import. It includes the validations from the previous section without anyone having to remember them.

<TopicCard step="4" title="4. How a Revit–Excel plugin works" time="~8 min">

**Export:**

1. You pick the schedules or categories and the parameters.
2. The plugin generates an Excel workbook with one sheet per schedule.
3. **The first column is the unique ID**, hidden or locked.
4. Read-only columns are **locked** and shaded so nobody tries to edit them.
5. Type parameters are flagged as such.

**Import:**

1. It reads the workbook and matches each row to its element by ID, never by position.
2. **It validates before writing**: data type, units, allowed values, conflicts between rows of the same type, rows with no element.
3. It shows a **preview**: how many values will change, on which elements, and which rows have problems.
4. It writes everything in a single operation that can be undone in one step.
5. It keeps a **log**: which parameter, on which element, old and new value, who and when.

<TopicCard step="6" title="6. How to roll it out safely" time="~5 min">

**Step 1 · Define what data goes out and comes back.** Which categories, which parameters, which are editable and which are read-only.

**Step 2 · Test on a copy.** Export, change some values on purpose — including errors — and import. Check that the plugin catches the errors and that good values land on the right element.

**Step 3 · Use it on a real project.** With the preview always on: nobody imports without seeing the summary.

**Step 4 · Make it part of the standard.** Export templates per deliverable type, so everyone works the same way.
