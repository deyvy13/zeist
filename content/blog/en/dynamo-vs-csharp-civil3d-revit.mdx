## Why automate Civil 3D or Revit (even though "the software already does a lot")

Every BIM/CAD software gives you powerful tools out of the box. But **every office has its own way of working**: naming standards, output formats, specific quantity criteria, internal checks, custom tables. That's the part you end up doing by hand. **And by hand, every single day, it gets expensive.**

BIM automation targets that 20% of tasks that soaks up 80% of the team's time. Two paths:

- **Dynamo:** visual programming inside Revit or Civil 3D itself.
- **C# / VB.NET:** compiled add-ins (plugins) that integrate into the software.

Both are official. Both are valid. Which one makes sense depends on the case — and that's what we're covering.

<Callout type="info" title="The 3 terms you'll see throughout this article">
- **Plugin (or "add-in")** — a small file that adds new buttons and functions to Civil 3D or Revit. Like a browser extension, but for BIM software.
- **API** — the official list of things Autodesk lets your code do to Civil 3D or Revit. Think of it as "the menu" — you can only order what's on it.
- **C#** — the official programming language for building Autodesk plugins. Pronounced "C sharp." Sounds intimidating, but with AI as a copilot, it's no longer the barrier it used to be.
</Callout>

<TopicCard step="1" title="1. What is Dynamo?" time="~5 min">

**Dynamo** is a **visual programming** environment built into Revit (and available as the `Dynamo for Civil 3D` package). Instead of writing code, you drag **nodes** (little boxes that each do a task) and connect them with **wires** that carry data.

**Simple example.** Renaming every line of type "Steel beam" to "VM-XX-###" based on its level:

- An `All Elements of Category` node grabs all the beams.
- An `Element.Name` node extracts their name.
- A `String.Concat` node builds the new name.
- An `Element.SetParameterValueByName` node applies it.

**Real advantages:**
- Very low learning curve — an engineer can be productive within a week.
- Instant iteration: change a node and see the effect without recompiling.
- Ideal for parametric geometry (facades, slopes, meshes).
- Saves as a shareable `.dyn` file you can send by email.

**Limitations:**
- Large graphs become unreadable ("spaghetti").
- Slower execution than native code (barely matters for small cases).
- Distributing to 50 users requires each one to open the `.dyn` file (or use Dynamo Player).
- No graphical interface of its own — the user sees the graph or simple inputs.

</TopicCard>

<TopicCard step="2" title="2. What does coding in C# for Civil 3D or Revit mean?" time="~5 min">

A **C# add-in** is a compiled plugin (`.dll`) that installs into Revit or Civil 3D and adds **buttons, commands, windows, and panels** to the software. It uses Autodesk's **official API**: a library of thousands of classes that give access to *everything* in the model (elements, families, parameters, views, sheets).

**Simple example.** A button on the toolbar labeled "Export quantities" that:

- Loops through every beam in the model.
- Extracts length, section, material.
- Generates an `.xlsx` file with the corporate format.
- Installs once, available for the whole team.

**Real advantages:**
- **Native performance** — processes thousands of elements in seconds.
- Distributable as an `.msi` installer for the whole company.
- Professional graphical interface (WinForms, WPF, custom toolbar buttons).
- Maintainable code with version control (Git).
- Can be digitally signed to install without warnings.

**Limitations:**
- Steeper learning curve — 2-3 months to become productive.
- Requires Visual Studio and a compile cycle.
- Every Revit/Civil 3D version can break the API — it needs upkeep.
- Live debugging requires setting up "attach to process."

</TopicCard>

<TopicCard step="3" title="3. When should you use Dynamo?" time="~5 min">

Use **Dynamo** when:

- **You're exploring or prototyping.** You don't yet know if the automation is worth it; you want to test it fast.
- **You're working with complex parametric geometry.** Facades, slopes with expressions, structural meshes, pipes following alignments.
- **Only one person or a small team will use the script.** No need to distribute to 100 users.
- **You need to iterate in hours, not days.** Last-minute client changes that require regenerating geometry.
- **The inputs are visual model data** (select these lines, transform these surfaces). Dynamo shines here.
- **You don't want to invest in learning a language.** A civil engineer or architect can pick it up on their own.

**Ideal Dynamo cases:**

- Generating parametric facades with height and undulation variables.
- Placing railings following existing stairs.
- Modeling slopes in Civil 3D from a polyline plus rules.
- Pulling data from the model into Excel for a one-off analysis.
- Automating repetitive drawings (profiles every X meters, typical sections).

<Callout type="tip">
Rule of thumb: if the task will be done **fewer than 20 times a month** or **by fewer than 5 people**, Dynamo is probably the best option. The investment doesn't justify a C# add-in.
</Callout>

</TopicCard>

<TopicCard step="4" title="4. When should you use C#?" time="~5 min">

Use **C#** when:

- **The automation will be used every day** by the whole team (10, 50, 500 people).
- **You need speed.** Processing 20,000 elements on a large model. Dynamo chokes; C# handles it in seconds.
- **You need your own interface** — a side panel, a window with forms, a configuration wizard. Dynamo can't do that.
- **You'll integrate with external systems** — SQL databases, REST APIs, ERP systems, in-house tools.
- **The logic is complex** — dozens of cases, cross-validations, business rules. In Dynamo it becomes unmanageable.
- **You need long-term maintainability** — code in Git, tests, pull requests, code review.
- **You'll distribute it as a product** — to external clients, with an installer, licensing, updates.

**Ideal C# cases:**

- Quantity-export add-in with corporate formatting and validation.
- Standards checker (naming, allowed families, required parameters).
- "Model health" panel — errors, warnings, uncategorized elements.
- Mass generation of sheets and drawings with automatic naming.
- Syncing model parameters with a SQL database / ERP.
- Analysis tools: evacuation routes, preliminary thermal calculations.

</TopicCard>

## How to get started without making mistakes

> 📘 **Pillar guide:** this article is part of [automating Civil 3D: the complete guide](/en/blog/automatizar-civil-3d-guia-completa), where you'll find the full picture of the topic.

A realistic plan for a team just starting out:

1. **List your 10 most repetitive tasks.** Note how much time they consume per week.
2. **Prioritize the 3 with the best savings-to-complexity ratio.** The obvious ones, not the ambitious ones.
3. **Prototype the first one in Dynamo.** Validate that the logic works. Fast, cheap.
4. **If it gets heavy use:** port it to C#. Distribute it to the whole team. Measure the real savings.
5. **Repeat monthly.** The ROI compounds.

It's also worth documenting each automation: what it does, who maintains it, what breaks if the software version changes. Without that, the team loses the knowledge the moment that person leaves.

## What if I want to learn it myself?

Solid, free resources:

- **Dynamo:** [primer.dynamobim.org](https://primer.dynamobim.org) — the official manual, comprehensive, in English.
- **Revit API:** [Autodesk Revit API Docs](https://www.revitapidocs.com), and the book *Autodesk Revit 2024 API Developer's Guide*.
- **Civil 3D API:** SDK downloadable from Autodesk's developer portal (search "Civil 3D SDK").
- **C# basics:** Microsoft's official tutorial or [freeCodeCamp](https://www.freecodecamp.org). If you've never coded before, start with our [route to learning to code from scratch](/en/blog/aprende-a-programar-desde-cero).
