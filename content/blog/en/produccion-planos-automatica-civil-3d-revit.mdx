<Callout type="success" title="Quick answer">
Civil 3D includes **plan production tools** that create view frames along an alignment and generate **plan and profile sheets** from a template; it can also create **cross-section** views and sheets. Revit creates sheets one at a time, with view templates helping keep a consistent look. What neither solves alone is the work around them: **filling the title block, numbering, placing consistent notes and labels, managing revisions, and exporting the full set** with the firm's naming convention. A **plan production plugin** automates that part and regenerates the whole set when the design changes.
</Callout>

<Callout type="info" title="Glossary: the terms you'll read, in plain language">
- **Sheet** — Each page of the drawing set that gets submitted or printed.
- **Plan and profile** — The standard road and utility sheet: plan view on top, longitudinal profile of the same stretch below.
- **View frame** — The rectangle that defines which stretch of the alignment goes on each sheet.
- **Viewport** — The window on the sheet that shows a view of the model at a given scale.
- **Title block** — The box with the sheet's data: project, number, title, scale, date, revision, signatures.
- **View template** — The settings that define how a view looks: scale, visible layers, styles.
- **Plugin** — A program installed inside Civil 3D or Revit that adds its own buttons to the toolbar at the top.

No programming jargon. This is written for designers, coordinators and design managers.
</Callout>

## The part of the project nobody budgets for

On a 5-mile road project, the drawing set can have 40 plan and profile sheets, as many cross-section sheets, plus details and structures. Every sheet goes through the same hands:

- Frame the stretch and set the scale
- Check that plan and profile cover the same stretch
- Place match lines and references to neighboring sheets
- Fill the title block: number, title, stations, date, revision
- Fix labels that overlap
- Export to PDF with the right file name

None of these tasks is hard. Together they're **days of work per submittal**. And the night before a deadline, when the alignment changes, a good part has to be redone.

<TopicCard step="1" title="1. What Civil 3D automates natively" time="~6 min">

Civil 3D has solid plan production tools, and it's worth using them before thinking about building anything.

**View frames.** It splits the alignment into stretches that fit on a sheet, based on the chosen template and scale, and places match lines between them.

**Plan and profile sheets.** From the view frames, it creates sheets with a plan viewport and a profile viewport, using a drawing template with the title block.

**Cross sections.** It creates multiple section views along the alignment and lays them out on sheets according to a template.

**Sheet sets.** The Sheet Set Manager groups the sheets and lets you number and publish them together, with fields that fill the title block.

<Callout type="info" title="Use them well before automating">
Many offices don't take advantage of these tools because they never built a good template. A template with the firm's title block, scales and styles already solves much of the framing. That's step one, plugin or not.
</Callout>

</TopicCard>

<TopicCard step="2" title="2. Where the native tools fall short" time="~6 min">

The native tools solve the geometry of the sheets. What's still manual is everything that turns them into **a submittable drawing set**:

- **Title blocks with project data**: start and end stations of each stretch, titles in the client's naming, sheet codes per the agency's standard.
- **Overlapping labels** on tight curves or crossings, moved by hand.
- **Notes and references** specific to each stretch: structures, crossings, section changes.
- **Revisions**: which sheets changed, with what description and on what date.
- **Exporting** the full set with the file naming the client requires.
- **Regenerating everything** when the alignment changes, without losing manual adjustments.

<TopicCard step="3" title="3. In Revit: sheets one at a time" time="~5 min">

In Revit, each sheet is created by hand: pick the title block, drag in the views, align them, fill in the parameters. View templates help keep everything consistent, but building is still sheet by sheet.

On a building with 120 sheets — floor plans per level, sections, elevations, details, schedules — that's a lot of time, plus a risk of inconsistency: views in different positions on each sheet, gaps in numbering, title blocks with stale data.

**What takes the most time in Revit:**

- Creating dozens of sheets with their number and name.
- Placing each view **in the same position** on every sheet of the same type.
- Duplicating views per level with the right template.
- Filling and updating title block parameters.
- Printing or exporting the full set with correct file names.

</TopicCard>

<TopicCard step="4" title="4. How a plan production plugin works" time="~8 min">

The idea: **the drawing set is described in a list, and the plugin builds it**.

**Step 1 · The sheet list.** A table — in Excel or inside the program — with each sheet: number, title, type, which views it carries, stretch or level.

**Step 2 · Generation.** The plugin creates the missing sheets, places views in fixed positions by sheet type, and applies the right view templates.

**Step 3 · Title block.** It fills each sheet's data from the list and from the model: in Civil 3D, for example, the start and end stations of each stretch; in Revit, level, discipline and phase.

**Step 4 · Labeling.** It applies label styles and flags overlaps that need human review.

**Step 5 · Revisions.** It records which sheets changed since the last submittal and updates the revision table.

**Step 6 · Export.** It exports the full set to PDF and DWG with the client's file naming, in a single step.
