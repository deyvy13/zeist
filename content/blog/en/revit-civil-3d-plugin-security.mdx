<Callout type="success" title="Quick answer">
A Revit or Civil 3D plugin is protected on five fronts: libraries without known vulnerabilities, a supported .NET version, code signing, installation in trusted folders and no passwords in the code. Mind the date: .NET 8, which the 2025 and 2026 releases run on, stops getting security patches on November 10, 2026.
</Callout>

<Callout type="info" title="Glossary: the terms you'll read, in plain English">
- **Plugin or add-in** — A program that installs inside Revit or Civil 3D and adds buttons to the top toolbar.
- **.NET** — Microsoft's platform that C# plugins run on.
- **Library** — Third-party code a plugin reuses, for example to read an Excel file. In .NET, libraries come as NuGet packages.
- **Code signing** — A certificate that identifies who made the plugin and shows nobody changed it.
- **Trusted folder** — A folder AutoCAD and Civil 3D load programs from without asking.
</Callout>

## Can a Revit or Civil 3D plugin have vulnerabilities?

Yes. A plugin runs inside the program with the same permissions as your user: it opens, changes and saves models and files. If it has a flaw, the flaw has that same reach. The risk concentrates in six places:

| Risk | What happens | How it's handled |
|---|---|---|
| Libraries with known flaws | An outdated library carries its flaw into the plugin | Check them with NuGet Audit before every release |
| Unsupported .NET | Microsoft stops shipping patches | Build for the .NET version of each release |
| Unsigned plugin or installer | Nobody can verify who made it or whether it was tampered with | Sign the DLLs and the installer |
| Open folders | AutoCAD and Civil 3D load code from anywhere | SECURELOAD at 1 or 2, plus trusted paths |
| Passwords in the code | Anyone with the DLL can read them | Keep them outside the plugin |
| Unvalidated outside data | A malformed Excel or CSV file changes the model | Validate it before touching the model |

## What changes on November 10, 2026?

Support for **.NET 8 and .NET 9** ends that day: Microsoft stops shipping security patches. **Revit, AutoCAD and Civil 3D 2025 and 2026** load plugins on .NET 8. The **2027** releases use **.NET 10**, supported through November 2028.

Plugins keep working, but the platform underneath stops getting patches. The sensible plan: keep Windows and .NET updated until then, plan the move to the 2027 releases, and rebuild and test your plugins for .NET 10.

## What does "Security – Unsigned Add-In" mean in Revit?

Revit shows that prompt at startup when a plugin isn't signed with a certificate from a trusted authority. It offers three choices: always load it, load it just this once, or don't load it.

Don't pick "always load" if you don't know who made the plugin. A signed plugin identifies its author and shows nobody changed it after it was published.

## What about AutoCAD and Civil 3D?

AutoCAD and Civil 3D decide which programs to load with the **SECURELOAD** system variable. At **1**, the default, they warn when a file comes from a folder that isn't trusted. At **2**, they only load from the folders in TRUSTEDPATHS. At **0** they load anything without asking, which Autodesk doesn't recommend. Keep it at 1 or 2 and install plugins only in trusted folders.
