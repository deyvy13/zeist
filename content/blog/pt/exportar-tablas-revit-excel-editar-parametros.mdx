<Callout type="success" title="Resposta rápida">
O Revit permite **exportar uma tabela** para um arquivo de texto delimitado que o Excel abre, mas **não tem uma forma nativa de importar as alterações de volta** ao modelo. Para editar parâmetros em massa no Excel e devolvê-los ao Revit usa-se o **Dynamo** — que tem nós para ler e escrever planilhas — ou um **plugin de sincronização Revit–Excel**. A chave técnica é incluir na planilha o **identificador único de cada elemento**, bloquear as colunas que não podem ser editadas e validar os dados antes de escrevê-los, para que nenhum valor vá parar no elemento errado.
</Callout>

<Callout type="info" title="Glossário: os termos que você vai ler, em linguagem simples">
- **Tabela** — A tabela do Revit que lista elementos e seus dados: portas, ambientes, paredes, equipamentos.
- **Parâmetro** — Cada dado de um elemento: código, material, fabricante, item de orçamento, área.
- **Parâmetro de tipo e de instância** — O de tipo é comum a todos os elementos daquele tipo; o de instância é próprio de cada elemento.
- **Identificador único** — O código interno de cada elemento, que não muda. É o que permite saber a qual elemento corresponde cada linha.
- **Parâmetro somente leitura** — Um que o Revit calcula e não pode ser escrito, como a área de um ambiente.
- **Ida e volta** — Exportar para o Excel, editar e devolver as alterações ao modelo.
- **Plugin** — Um programa instalado dentro do Revit que adiciona botões próprios na barra superior.

Sem termos de programação. Escrito para coordenadores BIM, modeladores e gerentes de projeto.
</Callout>

## Por que todo mundo quer o Excel

Há dados que se carregam muito mais rápido numa planilha do que no modelo:

- **Códigos de orçamento** para que o quantitativo saia organizado pelos itens.
- **Códigos de ativos e fabricantes** para a entrega ao cliente que vai operar o edifício.
- **Nomes e números de ambientes** de um projeto grande.
- **Classificações** que o cliente ou o órgão exige.
- **Dados de portas, janelas e equipamentos** que chegam de um fornecedor numa planilha.

No Excel se filtra, se copia para baixo, se ordena e se revisa num relance. No Revit, cada valor é um clique num elemento. Por isso todas as equipes acabam querendo o mesmo fluxo: **tirar os dados, editá-los no Excel e devolvê-los**.

<TopicCard step="1" title="1. O que o Revit permite nativamente" time="~5 min">

**Exportar, sim.** O Revit exporta qualquer tabela para um arquivo de texto delimitado, que o Excel abre sem problema. Útil para relatórios e quantitativos.

**Importar, não.** Não há opção nativa para pegar esse arquivo editado e atualizar os parâmetros do modelo. A ida e volta para na metade.

**Editar dentro da tabela, sim, mas devagar.** Dá para escrever valores na tabela e eles se aplicam ao elemento. Para dezenas de valores funciona. Para milhares, é a semana de trabalho de que falávamos.

<TopicCard step="2" title="2. Por que a ida e volta é delicada" time="~7 min">

Devolver dados ao modelo parece trivial, e é onde mais modelos se danificam. Estes são os riscos reais:

**Linhas que perdem o seu elemento.** Se a planilha não tem o identificador único de cada elemento, ao ordenar ou filtrar no Excel já não se sabe qual linha corresponde a qual porta. O valor vai parar em outro elemento.

**Parâmetros somente leitura.** A área de um ambiente ou o comprimento de uma parede são calculados pelo Revit. Se alguém os edita no Excel, a importação não consegue escrevê-los — ou pior, tenta e falha pela metade.

**Tipo versus instância.** Mudar um parâmetro de tipo numa linha muda **todos** os elementos daquele tipo. Se no Excel duas linhas do mesmo tipo foram editadas de forma diferente, um dos valores se perde.

**Formatos e unidades.** Um número guardado como texto, uma vírgula decimal no lugar de ponto, metros no lugar de milímetros.

**Linhas duplicadas ou apagadas.** Alguém copia uma linha para "adicionar" um elemento que não existe no modelo, ou apaga uma linha achando que assim apaga o elemento.

<Callout type="warn" title="O erro que ninguém vê">
O pior caso não é a importação falhar: é funcionar **com o valor no elemento errado**. Sem erro, sem aviso, e o dado ruim aparece meses depois no quantitativo ou na entrega ao cliente.
</Callout>

</TopicCard>

<TopicCard step="3" title="3. Dynamo ou plugin: dois caminhos válidos" time="~6 min">

O **Dynamo** tem nós para ler e escrever planilhas do Excel. Com um grafo bem montado dá para exportar, editar e importar. É uma boa opção para um caso pontual ou para testar a lógica.

Seus limites aparecem no uso diário: depende de quem sabe abrir o grafo, o tratamento de erros é básico e, com milhares de elementos, fica lento. Validar cada valor antes de escrevê-lo exige um grafo complexo.

Um **plugin de sincronização** é um botão na barra superior: exportar, editar, importar. Inclui as validações da seção anterior sem que ninguém precise lembrar delas.

<TopicCard step="4" title="4. Como funciona um plugin Revit–Excel" time="~8 min">

**Exportar:**

1. Você escolhe as tabelas ou categorias e os parâmetros.
2. O plugin gera um arquivo do Excel com uma planilha por tabela.
3. **A primeira coluna é o identificador único**, oculta ou bloqueada.
4. As colunas somente leitura ficam **bloqueadas** e com outra cor, para que ninguém tente editá-las.
5. Os parâmetros de tipo são marcados como tal.

**Importar:**

1. Lê o arquivo e emparelha cada linha com seu elemento pelo identificador, nunca pela posição.
2. **Valida antes de escrever**: tipo de dado, unidades, valores permitidos, conflitos entre linhas do mesmo tipo, linhas sem elemento.
3. Mostra um **resumo prévio**: quantos valores vão mudar, em quais elementos e quais linhas têm problemas.
4. Escreve tudo numa única operação, que pode ser desfeita de uma vez.
5. Guarda um **registro**: qual parâmetro, em qual elemento, valor anterior e novo, quem e quando.

Os dados do modelo deixam de depender da paciência de um modelador. Carregar a informação que o cliente pede — códigos, classificações, dados de ativos — passa de uma semana para uma tarde, e cada alteração fica registrada com o valor anterior.

<TopicCard step="5" title="5. Os usos que mais economizam horas" time="~5 min">

**Codificação para quantitativos e orçamentos.** Atribuir o código de orçamento a cada elemento para que o quantitativo saia organizado pelos itens.

**Dados para a entrega ao cliente.** Fabricante, modelo, garantia, código de ativo. O cliente que vai operar o edifício precisa deles no modelo.

**Ambientes e espaços.** Nomes, números, usos e acabamentos de projetos com centenas de ambientes.

**Revisão de qualidade dos dados.** Exportar para detectar parâmetros vazios ou inconsistentes antes de uma entrega, corrigi-los na planilha e devolvê-los.

<TopicCard step="6" title="6. Como implantar sem riscos" time="~5 min">

**Passo 1 · Defina que dados vão e voltam.** Quais categorias, quais parâmetros, quais são editáveis e quais só de consulta.

**Passo 2 · Teste numa cópia.** Exporte, mude alguns valores de propósito — inclusive com erros — e importe. Verifique que o plugin detecta os erros e que os valores bons chegam ao elemento certo.

**Passo 3 · Use num projeto real.** Com a revisão prévia sempre ativa: ninguém importa sem ver o resumo.

**Passo 4 · Torne parte do padrão.** Modelos de exportação por tipo de entrega, para que todos trabalhem igual.

</TopicCard>
