## Antes de começar: o que é programar (e o que não é)

Programar **não** é decorar a sintaxe de uma linguagem. Programar é **descrever a solução de um problema em passos que um computador consegue seguir**. A linguagem (Python, JavaScript, Rust, C…) é apenas o idioma em que você escreve essa solução. Mudar de linguagem depois é fácil; o difícil —e o importante— é aprender a pensar como programador.

Este guia foca exatamente nisso. Usaremos exemplos em **Python e JavaScript** por serem as duas linguagens mais acessíveis hoje, mas os conceitos são universais.

<Roadmap />

<TopicCard step="1" title="1. Lógica de programação: aprender a pensar" time="~2 h">

A **lógica de programação** é a habilidade de pegar um problema grande e quebrá-lo em passos pequenos, ordenados e sem ambiguidade. **Antes de tocar no teclado**, você precisa conseguir explicar para outra pessoa —em palavras— como resolveria o problema.

**Exemplo clássico:** fazer um sanduíche. Parece trivial até você tentar dar instruções para alguém que nunca viu um:

1. Pegue duas fatias de pão.
2. Coloque uma em um prato.
3. Passe manteiga sobre essa fatia.
4. Coloque presunto por cima.
5. Coloque queijo em cima do presunto.
6. Cubra com a segunda fatia.

Cada passo é uma instrução **atômica** (não dá para dividir mais) e **ordenada** (se você trocar a ordem, o resultado muda). É assim que um programador pensa.

**Exercício:** descreva, passo a passo, como alguém pode saber se um número é par ou ímpar. Sem código. Apenas palavras.

</TopicCard>

<TopicCard step="2" title="2. Pseudocódigo: a solução antes do código" time="~3 h">

O **pseudocódigo** é um intermediário entre a linguagem humana e a linguagem de programação. Ele te obriga a estruturar sua solução **antes** de se preocupar com sintaxe. É a ferramenta mais útil —e a que quase ninguém ensina bem— para iniciantes.

Um exemplo. Problema: **dizer se uma pessoa é maior de idade.**

```text
INÍCIO
  LER idade
  SE idade É MAIOR OU IGUAL A 18 ENTÃO
    MOSTRAR "É maior de idade"
  SENÃO
    MOSTRAR "É menor de idade"
  FIM SE
FIM
```

Notas: `INÍCIO/FIM`, `LER`, `MOSTRAR`, `SE/SENÃO/FIM SE` são palavras-chave do pseudocódigo. Não há uma norma universal —cada livro varia— mas a essência é sempre a mesma: **descrever o algoritmo com clareza**.

<Callout type="tip" locale="pt">
Quando você tiver 20 problemas resolvidos em pseudocódigo, traduzi-los para Python ou JavaScript vai ser questão de aprender vocabulário, não de aprender a pensar.
</Callout>

</TopicCard>

<TopicCard step="3" title="3. Variáveis e tipos de dados" time="~2 h">

Uma **variável** é um nome que você dá a um espaço de memória onde guarda um valor. O **tipo** diz que classe de valor é: número, texto, verdadeiro/falso etc.

**Os tipos mais comuns:**

- **Número inteiro** (`int`): `10`, `-5`, `2026`
- **Número decimal** (`float`): `3.14`, `-0.5`
- **Texto** (`string`): `"Olá"`, `'programação'`
- **Booleano** (`bool`): `true` ou `false`

Em Python:

```python
idade = 25
nome = "Ana"
altura = 1.72
eh_estudante = True
```

Em JavaScript:

```javascript
const idade = 25;
const nome = "Ana";
const altura = 1.72;
const ehEstudante = true;
```

**Convenção:** use nomes descritivos. `x` não diz nada; `idade_usuario` diz tudo.

</TopicCard>

<TopicCard step="4" title="4. Operadores: manipular e comparar valores" time="~1 h">

Operadores são símbolos que fazem operações com valores. Se dividem em três famílias.

**Aritméticos** (matemática básica):

| Operador | Uso | Resultado |
|----------|-----|-----------|
| `+` | `5 + 3` | `8` |
| `-` | `5 - 3` | `2` |
| `*` | `5 * 3` | `15` |
| `/` | `10 / 4` | `2.5` |
| `%` | `10 % 3` | `1` (resto) |

**De comparação** (retornam `true` ou `false`):

| Operador | Significado |
|----------|-------------|
| `==` | igual a |
| `!=` | diferente de |
| `>` | maior que |
| `<` | menor que |
| `>=` | maior ou igual |
| `<=` | menor ou igual |

**Lógicos** (combinam booleanos):

- `and` / `&&` — verdadeiro se **ambos** forem verdadeiros
- `or` — verdadeiro se **pelo menos um** for verdadeiro
- `not` / `!` — inverte o valor

</TopicCard>

<TopicCard step="5" title="5. Condicionais: tomar decisões" time="~2 h">

Condicionais são a primeira ferramenta de **controle de fluxo**: permitem que seu programa faça uma coisa ou outra dependendo dos dados. Sem condicionais, um programa é apenas uma lista linear de instruções.

Estrutura básica: `se` **condição** for verdadeira, **faça isto**; senão, **faça aquilo**.

Python:

```python
idade = 20

if idade >= 18:
    print("Você pode votar")
else:
    print("Ainda não pode votar")
```

JavaScript:

```javascript
const idade = 20;

if (idade >= 18) {
  console.log("Você pode votar");
} else {
  console.log("Ainda não pode votar");
}
```

Para mais de dois casos, encadeia com `elif` (Python) ou `else if` (JS):

```python
nota = 85

if nota >= 90:
    print("Excelente")
elif nota >= 70:
    print("Aprovado")
else:
    print("Reprovado")
```

</TopicCard>

<TopicCard step="6" title="6. Laços: repetir sem escrever a mais" time="~3 h">

Um **laço** repete um bloco de código enquanto uma condição for verdadeira. É a diferença entre escrever "Olá" uma vez ou um milhão: com laços, o tamanho do código não muda.

**Laço `for`** — quando você sabe quantas vezes quer repetir:

```python
for i in range(5):
    print(f"Iteração {i}")
# Imprime 0, 1, 2, 3, 4
```

**Laço `while`** — quando você não sabe quantas vezes, mas sabe quando parar:

```python
tentativas = 0
senha = ""

while senha != "abrete":
    senha = input("Senha: ")
    tentativas += 1

print(f"Acertou em {tentativas} tentativas")
```

<Callout type="warn" locale="pt">
Cuidado com laços infinitos: se a condição do `while` **nunca** ficar falsa, seu programa trava. É o erro #1 de iniciantes.
</Callout>

</TopicCard>

<TopicCard step="7" title="7. Funções: reutilizar lógica" time="~3 h">

Uma **função** é um bloco de código com nome, que você pode executar quantas vezes quiser. Recebe **parâmetros** (dados de entrada) e opcionalmente devolve um **resultado**. São o coração do código organizado.

Sem função (ruim):

```python
preco1 = 100
imposto1 = preco1 * 0.18
total1 = preco1 + imposto1

preco2 = 250
imposto2 = preco2 * 0.18
total2 = preco2 + imposto2
```

Com função (bom):

```python
def calcular_total(preco):
    imposto = preco * 0.18
    return preco + imposto

total1 = calcular_total(100)
total2 = calcular_total(250)
```

**Princípio DRY** (*Don't Repeat Yourself*): se você escreve a mesma coisa duas vezes, extraia numa função. É uma das regras mais importantes que existem.

</TopicCard>

<TopicCard step="8" title="8. Estruturas de dados: guardar muitos valores" time="~4 h">

Até agora cada variável guarda um valor. As estruturas de dados deixam você guardar **muitos valores relacionados** sob um só nome.

**Listas / Arrays** — coleção ordenada, você acessa por posição:

```python
frutas = ["maçã", "pera", "uva"]
print(frutas[0])  # maçã
frutas.append("manga")
```

**Dicionários / Objetos** — coleção com chaves, você acessa por nome:

```python
usuario = {
    "nome": "Ana",
    "idade": 25,
    "ativo": True
}
print(usuario["nome"])  # Ana
```

Combinar os dois é o normal no mundo real:

```python
usuarios = [
    {"nome": "Ana", "idade": 25},
    {"nome": "Luis", "idade": 30},
]

for u in usuarios:
    print(u["nome"])
```

</TopicCard>

<TopicCard step="9" title="9. Programação orientada a objetos (POO)" time="~5 h">

A **POO** organiza o código em **classes** (moldes) e **objetos** (instâncias do molde). Uma classe agrupa dados (**atributos**) e comportamento (**métodos**) que andam juntos.

Exemplo: modelar um usuário.

```python
class Usuario:
    def __init__(self, nome, idade):
        self.nome = nome
        self.idade = idade

    def saudar(self):
        return f"Olá, sou {self.nome}"

ana = Usuario("Ana", 25)
print(ana.saudar())  # Olá, sou Ana
```

Os quatro pilares clássicos: **encapsulamento** (agrupar dados e métodos), **herança** (uma classe herda de outra), **polimorfismo** (mesma chamada, comportamentos diferentes), **abstração** (esconder o detalhe). Não decore agora — se entende praticando.

</TopicCard>

<TopicCard step="10" title="10. Algoritmos básicos e complexidade" time="~4 h">

Um mesmo problema tem várias soluções possíveis. Um **algoritmo** é uma solução concreta, e alguns são mais rápidos que outros. Aprender a medir isso se chama **complexidade**.

Os três algoritmos que **todo mundo** deve conhecer:

1. **Busca linear** — você percorre uma lista do começo ao fim. Complexidade **O(n)**.
2. **Busca binária** — divide a lista pela metade a cada passo (requer que esteja ordenada). Complexidade **O(log n)**, muito mais rápida.
3. **Ordenação** — do menor ao maior. Os clássicos: *bubble sort* (lento mas pedagógico) e *merge sort* / *quick sort* (os usados em produção).

<Callout type="info" locale="pt">
A **notação O(n)** (Big O) é a forma padrão de comparar algoritmos. `O(1)` é instantâneo, `O(log n)` é rapidíssimo, `O(n)` é linear, `O(n²)` é lento com listas grandes.
</Callout>

</TopicCard>

<TopicCard step="11" title="11. Seu primeiro projeto real" time="~10-20 h">

Livros não te transformam em programador. Projetos, sim. Escolha um pequeno mas **completo**, e termine-o. Terminar importa mais do que fazer perfeito.

**Ideias de primeiro projeto** (escolha uma):

- **Lista de tarefas no console** — adicionar, listar, marcar como concluídas, apagar. Salva num arquivo `.json`.
- **Calculadora de despesas pessoais** — registrar despesas, somar por categoria, mostrar média do mês.
- **Jogo de adivinhar o número** — o programa pensa um número, você tenta adivinhar, ele diz se é maior ou menor.
- **Conversor de moedas** — pede uma quantia e duas moedas, mostra a conversão (fixe as taxas ou chame uma API).

Qualquer um deles usa **tudo o que veio antes**: variáveis, condicionais, laços, funções, estruturas de dados, e provavelmente classes se você estruturar bem.

</TopicCard>
