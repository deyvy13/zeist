## Por que automatizar Civil 3D ou Revit (mesmo com "o software já fazendo muito")

Todo software BIM/CAD te dá ferramentas potentes por padrão. Mas **cada escritório tem seu jeito de trabalhar**: padrões de nomenclatura, formatos de saída, quantitativos específicos, checagens internas, tabelas próprias. Isso você acaba fazendo à mão. **E à mão, todos os dias, custa caro.**

A automação BIM ataca aqueles 20% de tarefas que absorvem 80% do tempo da equipe. Dois caminhos:

- **Dynamo:** programação visual dentro do próprio Revit ou Civil 3D.
- **C# / VB.NET:** add-ins (plugins) compilados que se integram ao software.

Os dois são oficiais. Os dois são válidos. Qual vale a pena depende do caso — e é para lá que vamos.

<TopicCard step="1" title="1. O que é Dynamo?" time="~5 min">

**Dynamo** é um ambiente de **programação visual** integrado no Revit (e disponível como pacote `Dynamo for Civil 3D`). Em vez de escrever código, você arrasta **nós** (caixinhas que fazem uma tarefa) e os conecta com **cabos** que transportam dados.

**Exemplo simples.** Renomear todas as linhas do tipo "Viga metálica" para "VM-XX-###" conforme o nível:

- Um nó `All Elements of Category` pega todas as vigas.
- Um nó `Element.Name` extrai o nome.
- Um nó `String.Concat` monta o novo nome.
- Um nó `Element.SetParameterValueByName` o aplica.

**Vantagens reais:**
- Curva de aprendizado baixíssima — um engenheiro pode ser produtivo em uma semana.
- Iteração instantânea: você muda um nó e vê o efeito sem recompilar.
- Ideal para geometria paramétrica (fachadas, taludes, malhas).
- Salva como arquivo `.dyn` compartilhável por e-mail.

**Limitações:**
- Grafos grandes viram ilegíveis ("spaghetti").
- Execução mais lenta que código nativo (importa pouco para casos pequenos).
- Distribuir para 50 usuários exige que cada um abra o `.dyn` (ou use Dynamo Player).
- Sem interface gráfica própria — o usuário vê o grafo ou inputs simples.

</TopicCard>

<TopicCard step="2" title="2. O que é programar em C# para Civil 3D ou Revit?" time="~5 min">

Um **add-in C#** é um plugin compilado (`.dll`) que se instala no Revit ou Civil 3D e adiciona **botões, comandos, janelas e painéis** ao software. Usa a **API oficial** da Autodesk: uma biblioteca com milhares de classes que dão acesso a *tudo* do modelo (elementos, famílias, parâmetros, vistas, pranchas).

**Exemplo simples.** Um botão na ribbon "Exportar quantitativo" que:

- Percorre todas as vigas do modelo.
- Extrai comprimento, seção, material.
- Gera um `.xlsx` com formato corporativo.
- Se instala uma vez, disponível para toda a equipe.

**Vantagens reais:**
- **Performance nativa** — processa milhares de elementos em segundos.
- Distribuível como instalador `.msi` para toda a empresa.
- Interface gráfica profissional (WinForms, WPF, botões próprios na ribbon).
- Código sustentável com controle de versão (Git).
- Pode ser assinado digitalmente para instalar sem avisos.

**Limitações:**
- Curva de aprendizado maior — 2-3 meses para ser produtivo.
- Requer Visual Studio e ciclo de compilação.
- Cada versão de Revit/Civil 3D pode quebrar a API — precisa manter.
- Debug ao vivo requer configurar "attach to process".

</TopicCard>

<TopicCard step="3" title="3. Quando usar Dynamo?" time="~5 min">

Use **Dynamo** quando:

- **Você está explorando ou prototipando.** Ainda não sabe se a automação vale a pena; quer testar rápido.
- **Trabalha com geometria paramétrica complexa.** Fachadas, taludes com expressões, malhas estruturais, tubulações seguindo alinhamentos.
- **O script será usado por uma pessoa ou equipe pequena.** Não precisa distribuir para 100 usuários.
- **Precisa iterar em horas, não dias.** Mudanças de última hora do cliente que exigem regenerar geometria.
- **Os inputs são dados visuais do modelo** (selecione estas linhas, transforme estas superfícies). Dynamo brilha aí.
- **Não quer investir em aprender uma linguagem.** Um engenheiro civil ou arquiteto pode aprender por conta.

**Casos ideais de Dynamo:**

- Gerar fachadas paramétricas com variáveis de altura e ondulação.
- Colocar guarda-corpos seguindo escadas existentes.
- Modelar taludes no Civil 3D a partir de uma polilinha + regras.
- Extrair dados do modelo e jogá-los no Excel para análise pontual.
- Automatizar desenhos repetitivos (perfis a cada X metros, seções tipo).

<Callout type="tip" locale="pt">
Regra de ouro: se a tarefa for feita **menos de 20 vezes por mês** ou **por menos de 5 pessoas**, Dynamo provavelmente é a melhor opção. O investimento não justifica um add-in C#.
</Callout>

</TopicCard>

<TopicCard step="4" title="4. Quando usar C#?" time="~5 min">

Use **C#** quando:

- **A automação será usada todos os dias** por toda a equipe (10, 50, 500 pessoas).
- **Precisa de velocidade.** Processar 20 000 elementos num modelo grande. Dynamo trava; C# faz em segundos.
- **Precisa de interface própria** — um painel lateral, uma janela com formulários, um wizard de configuração. Dynamo não dá conta.
- **Vai integrar com sistemas externos** — bancos SQL, APIs REST, sistemas ERP, ferramentas próprias.
- **A lógica é complexa** — dezenas de casos, validações cruzadas, regras de negócio. No Dynamo vira ingovernável.
- **Precisa de sustentabilidade a longo prazo** — código no Git, testes, pull requests, revisão de código.
- **Vai distribuir como produto** — a clientes externos, com instalador, licenciamento, atualizações.

**Casos ideais de C#:**

- Add-in de exportação de quantitativos com formato corporativo e validação.
- Verificador de padrões (naming, famílias permitidas, parâmetros obrigatórios).
- Painel de "Saúde do modelo" — erros, warnings, elementos sem categoria.
- Geração massiva de pranchas e desenhos com nomenclatura automática.
- Sincronização de parâmetros do modelo com banco SQL / ERP.
- Ferramentas de análise: rotas de evacuação, cálculos térmicos preliminares.

</TopicCard>

- **Geração massiva de pranchas** (uma por nível, com vista + tabela + selo) — Antes: 4-8 h/projeto. Com add-in: 2 minutos. **Economia ~98%.**
- **Exportar quantitativo por família em Excel corporativo** — Antes: 2 h/semana. Com add-in: 10 segundos. **Economia ~99%.**
- **Colocação de guarda-corpos paramétricos seguindo escadas** (Dynamo) — Antes: 1 h/projeto. Com Dynamo: 5 minutos. **Economia ~92%.**
- **Detector de interferências entre disciplinas + relatório** — Antes: 3 h/coordenação. Com add-in: 15 minutos incluindo revisão. **Economia ~92%.**

### Para Civil 3D

- **Geração de perfis longitudinais a cada X metros** — Antes: 3 h/trecho. Com Dynamo: 15 minutos. **Economia ~92%.**
- **Quantitativo automático de movimento de terra + tabela** — Antes: 2 h. Com add-in C#: 30 segundos. **Economia ~99%.**

Um escritório típico de 10 pessoas investe **~40-60 horas/semana** em tarefas repetitivas como as anteriores. Automatizar 5-6 delas economiza ~25-35 horas/semana na equipe — equivalente a **meio profissional adicional sem nova contratação**. Em um ano, isso paga com folga o desenvolvimento dos add-ins.

## Como começar sem errar

Um plano realista para a equipe que está começando:

1. **Liste suas 10 tarefas mais repetitivas.** Anote quanto tempo consomem por semana.
2. **Priorize as 3 com melhor razão economia/complexidade.** As óbvias, não as ambiciosas.
3. **Prototipe a primeira em Dynamo.** Valide que a lógica funciona. Rápido, barato.
4. **Se se usa muito:** porte para C#. Distribua para toda a equipe. Meça a economia real.
5. **Repita mensalmente.** O ROI se acumula.

Também vale documentar cada automação: o que faz, quem mantém, o que quebra se mudar a versão do software. Sem isso, a equipe perde o conhecimento quando essa pessoa sai.
